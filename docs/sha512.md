# SHA-512 家族

[sha512/sha512.go](../sha512/sha512.go) 实现 FIPS 180-4（2015）的 SHA-512、SHA-384、SHA-512/224 和 SHA-512/256。四种算法在同一个包中共用 64 位字核心、128 字节分块和 80 轮压缩，使用各自的初始值与输出长度。

| 算法 | 一次性入口 | 流式入口 | 输出字节数 | 初始值 / 计算章节 |
| --- | --- | --- | --- | --- |
| SHA-512 | `Sum512` | `New` | 64 | §5.3.5 / §6.4 |
| SHA-384 | `Sum384` | `New384` | 48 | §5.3.4 / §6.5 |
| SHA-512/224 | `Sum512_224` | `New512_224` | 28 | §5.3.6.1 / §6.6 |
| SHA-512/256 | `Sum512_256` | `New512_256` | 32 | §5.3.6.2 / §6.7 |

一次性函数接收 `[]byte` 并返回固定长度数组，流式构造函数返回 `hash.Hash`。只接受完整字节消息，`nil` 与空切片等价，输入及其底层数组保持不变。

## 从 SHA-256 迁移到 64 位字

先阅读 [SHA-256 导读](sha256.md)，再核对字长、块长、轮数、移位参数和长度字段。消息扩展仍由前 16 个大端字递推得到，但共有 80 个字：

```text
W[t] = σ1(W[t-2]) + W[t-7] + σ0(W[t-15]) + W[t-16]
σ0(x) = ROTR1(x) XOR ROTR8(x) XOR SHR7(x)
σ1(x) = ROTR19(x) XOR ROTR61(x) XOR SHR6(x)
Σ0(x) = ROTR28(x) XOR ROTR34(x) XOR ROTR39(x)
Σ1(x) = ROTR14(x) XOR ROTR18(x) XOR ROTR41(x)
```

所有加法按模 `2^64` 进行。80 轮结束后，工作变量加回输入状态；最终八个状态字按大端序编码，再按变体截取输出。

## 128 位长度字段

FIPS 180-4 §5.1.2 要求消息少于 `2^128` 比特，即完整字节消息少于 `2^125` 字节。实现使用 `totalBytesHigh`、`totalBytesLow` 两个 `uint64` 保存总字节数，低位加法溢出时向高位进一。写入前检查上限，越界则 panic。

填充在 `checkSum` 中完成：追加 `0x80`，补零到块内第 112 字节，再写入 16 字节大端比特长度。消息尾部为 111 字节时一个块足够，112 字节时需要两个块。由字节数转换为比特数时：

```text
bitsHigh = (bytesHigh << 3) | (bytesLow >> 61)
bitsLow  = bytesLow << 3
```

低字的最高三位必须进入高字，不能只对两个字分别左移。`Sum` 在状态副本上填充，不改变流式对象；一次性入口的实际输入大小仍受 Go 切片和可用内存限制。

## 变体的初始值与截断

SHA-384、SHA-512/224、SHA-512/256 都不能直接截取普通 SHA-512 的摘要，必须从各自的 IV 开始。SHA-512/224 输出 28 字节：前三个 64 位字和第四个字的高 32 位。`Reset` 必须保留变体选择并恢复对应 IV。

实现使用标准规定的四套固定初始值。任意参数的 SHA-512/t 初始向量生成算法不在当前接口范围内，可继续阅读 §5.3.6。

## 测试顺序

以下命令在仓库根目录运行，测试位于 [sha512/sha512_test.go](../sha512/sha512_test.go)。

| 步骤 | 标准章节 | 验证命令 |
| --- | --- | --- |
| 核对四种算法的固定向量 | NIST 示例 | `go test ./sha512 -run '^TestVectorFixtures$' -count=1 -v` |
| 消息扩展 `schedule512` | §§4.1.3、5.2.2、6.4.2 第 1 步 | `go test ./sha512 -run '^TestSchedule512$' -count=1 -v` |
| 压缩 `compress512` | §§4.1.3、4.2.3、6.4.2 第 2–4 步 | `go test ./sha512 -run '^TestCompress512$' -count=1 -v` |
| 四种摘要输出 | §§6.4–6.7 | `go test ./sha512 -run '^TestKnownAnswers$' -count=1 -v` |
| 计数器与长度编码 | §5.1.2 | `go test ./sha512 -run '^TestLength' -count=1 -v` |
| 完整测试 | 算法与流式接口 | `go test ./sha512 -count=1` |

消息扩展和压缩测试直接使用已填充的 `abc` 块，可独立于填充代码调试。扩展字检查点按标准推导；压缩预期来自 NIST 示例，包含最终状态累加。

`TestLengthAccounting` 检查低字进位、128 位计数与上限拒绝；`TestLengthPadding` 检查合成状态下的最终长度编码。这些测试不声称计算过实际的超大消息。其余测试覆盖四种变体、填充分界、多块输入、分块写入、`Sum` 状态保护、`Reset`、变体隔离和输入所有权。

```sh
# Compile without running tests.
go test ./sha512 -run '^$'

# Fuzz all four streaming variants against the standard library.
go test ./sha512 -run '^$' -fuzz '^FuzzStreamingAgainstStandard$' -fuzztime 10s
```

`TestVectorFixtures` 只核对向量录入，不能替代算法测试。`crypto/sha512` 仅用于测试对照；合成消息与官方固定向量分别标注。
