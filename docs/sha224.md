# SHA-224

SHA-224 与 SHA-256 共用 [sha256 包](../sha256/sha256.go) 的 32 位字核心。一次性入口为 `sha256.Sum224(data []byte) [28]byte`，流式入口为 `sha256.New224()`，返回 `hash.Hash`。实现和测试分别位于 [sha256.go](../sha256/sha256.go) 与 [sha256_test.go](../sha256/sha256_test.go)。

## 与 SHA-256 的区别

FIPS 180-4（2015）§§5.3.2、6.3 规定了 SHA-224 的初始状态和摘要输出。两种算法的块长、填充、消息扩展、64 轮压缩完全相同；区别在于初始状态和输出长度。

| 项目 | SHA-224 | SHA-256 |
| --- | --- | --- |
| 块大小 | 64 字节 | 64 字节 |
| 内部状态 | 8 个 32 位字 | 8 个 32 位字 |
| 初始值 | §5.3.2 | §5.3.3 |
| 输出 | 前 7 个状态字，28 字节 | 全部 8 个状态字，32 字节 |
| 流式入口 | `New224()` | `New()` |

不能直接截取 `Sum256` 的结果得到 SHA-224。压缩时仍需保留全部八个状态字，最后才取大端编码结果的前 28 字节。`Reset` 必须恢复 SHA-224 的 IV，而不是 SHA-256 的 IV。

## 阅读与测试

先阅读 [SHA-256 导读](sha256.md) 的填充、消息扩展与流式处理，再核对 `initialState224`、`is224` 和输出截断。两个变体都只接受完整字节消息，要求消息长度小于 `2^64` 比特。

在仓库根目录执行：

```sh
# Check the NIST SHA-224 fixture data.
go test ./sha256 -run '^TestSum224VectorFixtures$' -count=1 -v

# Test SHA-224 one-shot hashing and input ownership.
go test ./sha256 -run '^TestSum224' -count=1 -v

# Check independent initialization and reset behavior for both variants.
go test ./sha256 -run '^TestVariantIsolation$' -count=1 -v

# Run both variants, streaming contracts, and shared core tests.
go test ./sha256 -count=1
```

测试覆盖 NIST `abc` 和 56 字节消息、填充边界、多块输入、重复与交错调用，以及分块写入、`Sum` 后继续写入和输入不变性。补充消息的预期值来自 Go 标准库 `crypto/sha256`；它们与官方固定向量分别标注。向量录入核对不代表算法测试通过。
