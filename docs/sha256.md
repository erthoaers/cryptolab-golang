# SHA-256

[sha256/sha256.go](../sha256/sha256.go) 实现 FIPS 180-4（2015）的 SHA-256 和 SHA-224，共用填充、消息扩展与压缩逻辑。`Sum256`、`Sum224` 返回固定长度数组，`New`、`New224` 返回可分块写入的 `hash.Hash`。

| 算法 | 一次性入口 | 流式入口 | 摘要长度 |
| --- | --- | --- | --- |
| SHA-256 | `Sum256(data []byte)` | `New()` | 32 字节 |
| SHA-224 | `Sum224(data []byte)` | `New224()` | 28 字节 |

只接受完整字节消息，`nil` 与空切片等价。算法不会修改输入及其底层数组。SHA-224 的初始值与输出规则见 [SHA-224 导读](sha224.md)。

### 填充与长度

块长为 64 字节。最终处理时，在剩余消息后追加 `0x80`，补零到块内第 56 字节，再写入 8 字节大端比特长度。尾部有 56 字节或更多时，需要额外一个块。重点比较 55、56、63、64 字节消息。

标准要求消息少于 `2^64` 比特。对于完整字节消息，`8 × byteLength < 2^64` 等价于 `byteLength < 2^61`，因此字节计数器的最大值是 `2^61 - 1`。必须先检查长度，再乘以八，避免溢出后丢失高位。

填充位于 `checkSum`，没有独立的 `pad` 函数。它使用自己的缓冲区，不能直接向输入切片追加填充，否则可能改写输入的剩余容量。

### 消息扩展

一个块按大端序解析为 16 个 `uint32`，然后扩展为 64 个字：

```text
W[t] = σ1(W[t-2]) + W[t-7] + σ0(W[t-15]) + W[t-16]
σ0(x) = ROTR7(x) XOR ROTR18(x) XOR SHR3(x)
σ1(x) = ROTR17(x) XOR ROTR19(x) XOR SHR10(x)
```

小写 sigma 用于扩展消息，大写 Sigma 用于压缩。源码采用 `smallSigma0_256`、`smallSigma1_256`、`bigSigma0_256`、`bigSigma1_256` 命名，保持 Go 包内可见。循环右移会把低位移回高位，逻辑右移则补零，二者不能混用。

### 压缩与状态累加

压缩使用八个工作变量，每轮先从旧值计算两个临时量，再同时更新工作变量。`uint32` 加法自然对应模 `2^32` 加法。64 轮结束后，把工作变量加回输入状态；下一块从累加后的状态继续。每次新建或重置摘要对象都复制 IV。

`TestSchedule256` 和 `TestCompress256` 直接使用固定的已填充 `abc` 块，不依赖填充实现。扩展检查点按标准独立推导；压缩预期包含最终状态累加。

## 流式接口

`Write` 累计字节数、压缩完整块，并缓存剩余字节。`Sum(prefix)` 在摘要状态的副本上完成填充，把摘要追加到 `prefix` 后面，不改变当前计算状态，因此可以重复调用或继续写入。`Reset` 恢复相应变体的 IV，并清空计数器与缓冲区长度。

接口测试覆盖分块位置、`Sum` 后继续写入、前缀保留、`Reset`、变体隔离、输入缓冲区复用和 `io.Reader` 集成。`TestStreamingLengthLimit` 使用合成内部状态检查长度边界，不实际分配接近上限的消息。

```sh
# Compile without running tests.
go test ./sha256 -run '^$'

# Fuzz one-shot hashing against the standard library.
go test ./sha256 -run '^$' -fuzz '^FuzzSum256AgainstStandard$' -fuzztime 10s

# Fuzz both streaming variants.
go test ./sha256 -run '^$' -fuzz '^FuzzStreamingAgainstStandard$' -fuzztime 10s
```

`TestVectorFixtures` 与 `TestSum224VectorFixtures` 只核对官方向量的录入。其余固定向量、标准库对照与接口测试用于验证实现；编译或向量核对不能代替它们。`crypto/sha256` 仅用于测试，生产代码自行实现算法。
