# Ed25519：从曲线点到确定性签名

本练习从小端整数、曲线点运算逐步构造 Ed25519 签名。入口为 [`ed25519/ed25519.go`](../ed25519/ed25519.go)，10 个算法函数保留 TODO；[分步测试](../ed25519/ed25519_test.go)和[官方向量](../ed25519/vectors_test.go)用于核对实现。

依据 **RFC 8032**（2017-01），算法定义见 [§5.1](https://www.rfc-editor.org/rfc/rfc8032.html#section-5.1)，测试向量见 [§7.1](https://www.rfc-editor.org/rfc/rfc8032.html#section-7.1)。本包只包含普通 Ed25519：输入 32 字节 seed，产生 32 字节公钥和 64 字节签名。Ed25519 是数字签名；X25519 是密钥协商，本练习不包含它。ctx/ph、随机种子生成、密钥文件格式和性能优化留待后续。

## 先分清两种模数

曲线为扭曲 Edwards 曲线：

\[
-x^2+y^2=1+dx^2y^2\pmod p,\qquad
p=2^{255}-19,\qquad d=-121665/121666\pmod p.
\]

坐标在有限域模 **p** 中计算；基点 B 的阶为

\[
L=2^{252}+27742317777372353535851937790883648493.
\]

签名标量模 **L** 计算。整个曲线群有 `8L` 个点，不能把任意曲线点都当作 B 生成的子群成员。单位元是 `(0,1)`，点的逆元是 `(-x,y)`；源码中的 `point{}` 含 nil 坐标，不是单位元。

首版使用仿射坐标和 `math/big`，允许 `Mod`、`ModInverse`、`Exp` 等基础整数运算。先理解数据流，再考虑 RFC §5.1.4 的扩展坐标。所有 `big.Int` 方法会改写接收者，结果与临时量应独立分配，不能改写输入点、标量或参数。

## 六步练习

命令均在 `cryptolab-golang/` 下运行。每个 TODO panic 都会使测试明确失败，不会跳过。

### ED-01：小端整数

补 `littleInt`、`littleBytes`，阅读 §5.1.2。与 RSA 的大端整数转换相反，最低有效字节在最前面；定长输出的补零位于末尾。`big.Int.SetBytes` / `Bytes` 使用大端，需要自行处理顺序。编码时先检查范围，不要用截断代替报错。

```sh
go test ./ed25519 -run '^TestLittle' -count=1 -v
```

### ED-02：点编码与恢复 x

补 `encodePoint`、`decodePoint`，阅读 §§5.1.2–5.1.3。编码保存 y 的 255 位和 x 的奇偶位，不是拼接两份坐标，也不是 x 的数值正负号。

解码先分离最高位，再检查 `y < p`。根据曲线方程恢复

\[
x^2=(y^2-1)/(dy^2+1)\pmod p.
\]

利用 `p ≡ 5 (mod 8)` 求平方根，检查候选根，再按奇偶位选择。必须拒绝不存在平方根的输入，以及 `x=0` 却将奇偶位设为 1 的编码。读取的 y 不能先取模，否则会接受非规范编码。原始输入长度必须恰为 32 字节。

```sh
go test ./ed25519 -run '^TestPoint(Encoding|Decoding.*)$' -count=1 -v
```

### ED-03：点加法与标量乘法

补 `addPoints`、`scalarMult`，阅读 §3 的仿射加法与 §5.1.4 的优化形式。先检查 `B+O=B`、`B+(-B)=O`、`B+B`，再用倍加法组合出 `[n]P`。

`scalarMult` 接受非负整数，不能无条件将 n 模 L 约简：例如阶为 2 的点 T 满足 `[L]T=T`，而不是单位元。基点路径允许利用 B 的阶，但通用入口必须保留原始整数的含义。零标量应返回新的单位元，结果不能别名引用输入。

```sh
go test ./ed25519 -run '^Test(PointAddition|ScalarMult)$' -count=1 -v
```

### ED-04：seed、秘密标量与公钥

补 `expandSeed`、`PublicKeyFromSeed`，阅读 §5.1.5。seed 是 32 字节输入，不直接当作标量。对 seed 求 SHA-512 后，前半部分按 RFC 修剪位，再以小端解释为秘密标量 s；后半部分原样保留为 prefix。`expandSeed` 返回修剪后的原始 s，不先模 L 约简。公钥编码 `[s]B`。

`hashParts` 已连接本库自写的 SHA-512，可用来计算多个字节片段拼接后的哈希。标准库 `crypto/ed25519`、`crypto/sha512` 仅供测试对照。Go 标准库的 64 字节私钥表示与这里的 32 字节 seed 不是同一个接口。

```sh
go test ./ed25519 -run '^Test(ExpandSeed|PublicKeyRFC8032)$' -count=1 -v
```

### ED-05：签名

补 `Sign`，阅读 §5.1.6。普通 Ed25519 的 `dom2` 为空，`PH(M)=M`。沿下面的关系检查每份数据的类型和长度：

\[
\begin{aligned}
r &= \operatorname{LE}(\operatorname{SHA512}(prefix\parallel M))\bmod L,\\
R &= [r]B,\\
k &= \operatorname{LE}(\operatorname{SHA512}(\operatorname{ENC}(R)\parallel A\parallel M))\bmod L,\\
S &= (r+ks)\bmod L.
\end{aligned}
\]

这里 A 是编码后的 32 字节公钥。输出 `ENC(R) || LE32(S)`。同一 seed 和消息必须产生相同签名；不要增加随机 nonce，也不要给消息额外做预哈希。官方 `TEST SHA(abc)` 是把一个 64 字节摘要当作普通消息签名，仍不是 Ed25519ph。

```sh
go test ./ed25519 -run '^TestSignRFC8032$' -count=1 -v
```

### ED-06：验签与拒绝边界

补 `Verify`，阅读 §§5.1.7、6.1、8.4。先检查长度与编码：A、R 必须能规范解码，收到的 S 必须小于 L，不能通过模约简“修复”越界签名。重新计算 k，再比较群等式。

本练习明确选择 RFC §5.1.7 允许的**不乘余因子等式**：

\[
[S]B=R+[k]A.
\]

k 按 §6.1 示例模 L 约简；A、R 的解码按 §5.1.3 严格检查。本练习没有额外的单位元或子群拒绝策略。因此它与乘 8 的等式、或另加子群限制的策略，在特殊输入上的接受集合不同。`TestVerifyPolicy` 固定此选择：`A=O,R=O,S=0` 满足等式；把 R 换成阶为 2 的点则不满足。接受单位元案例不表示它是安全的应用公钥；后续若研究应用层公钥策略，应单独设计并测试。

```sh
go test ./ed25519 -run '^TestVerify' -count=1 -v
```


全部 5 组 RFC §7.1 向量的消息长度为 0、1、2、1023、64 字节。额外测试覆盖编码边界、无平方根、x=0 的非法奇偶位、点运算、`S=L` / `S+L`、错误消息/公钥、篡改/截断签名、输入与底层备用容量保护，以及与 Go 标准库的有效签名双向互操作。标准库只作有效签名的差分依据，异常点的接受策略由 `TestVerifyPolicy` 单独约定。

从 **ED-01** 开始实现，逐步运行对应测试。修改 SHA-512 依赖后，应运行 `go test ./sha512 -count=1`，再核对 `TestHashParts`。完整 Ed25519 验收还需要所有点运算、签名与验签测试通过。

首版 `math/big` 与倍加法没有常数时间保证，适合学习和向量核对，不用于真实秘密。后续可以研究扩展坐标、固定宽度域运算、常数时间标量乘法，再独立规划 ctx/ph 与 Rust 版本；这些不计入当前验收。
